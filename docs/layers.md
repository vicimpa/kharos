# Слои: данные на карте и данные игрока

Единый механизм слоёв для Rust-симуляции (`docs/engine.md`, `boundary.md` (убран вместе с TS, в истории git)): всё, что лежит на карте по тайлам
или ячейкам и не является сущностью, — земля, покрытие, обзор, разведанное, память игроков, следы, месторождения. Слой
объявляется, а хранение, сохранение, синхронизация с TS и рассылка клиентам у всех слоёв общие. Новый слой — наш или
мода — это объявление и системы, которые в него пишут.

## 1. Что сейчас

Семь слоёв в `sim-ts`, каждый со своим кодом хранения, сохранения, рассылки и сброса:

| Слой | Где | Чей | Форма | Сохраняется |
|---|---|---|---|---|
| Земля | `shared/terrain.ts`, `Land` | мира | чанки 32×32, 4 байта на тайл | да, `LAND` |
| Покрытие | `paved.ts`, `Paving` | мира | тайл → код | да |
| Занятость | `buildings.ts`, `Occupancy` | мира | выводится из зданий | нет |
| Месторождения | `deposits.ts` | мира + призраки игрока | предметы по ячейкам 40×40 | да |
| Следы | `traces.ts` | мира | предметы по ячейкам 16×16, со сроком | нет |
| Обзор, разведанное | `vision.ts` | игрока | сетка на всю карту: 0 / 1 / 2 | разведанное — `EXPL` |
| Память о земле | `landMemory.ts` | игрока | правки, какими их видел | да |
| Память о покрытии | `paveMemory.ts` | игрока | тайлы, какими их видел | да |
| Память о зданиях | `buildMemory.ts` | игрока | снимки зданий, ушедших в туман | да |

Общее, написанное семь раз: изменённое с прошлого раза (`revision`, `drain`, `learned`, `takeLearned`), что отдать
игроку при входе (`knownEdits`, `knownPaving`, `map`), сохранение и загрузка (`save…`/`create…(save)`), сброс игрока
(`vision.forget`, `forgetBuildings`; память о земле и покрытии при этом не сбрасывается — уже расхождение). Три памяти
— одна идея: игрок знает ту версию, которую видел последней.

## 2. Решение

**[решено, 2026-10-16]** Слой — объявленные данные на карте. Объявление говорит, чей он, какой формы, что в нём
лежит и как его сохранять; движок даёт хранение, изменения, сохранение и синхронизацию одинаково для всех.

### Чей слой

- **Мира** — один на всех: земля, покрытие, следы.
- **Игрока** — свой у каждого игрока: обзор, разведанное, память. **[решено, 2026-10-16]** Живёт вместе с игроком: заводится, когда игрок
  появился, сохраняется **в его записи** сохранения, сбрасывается одним вызовом, когда игрок начинает заново,
  уходит в сеть только ему (и союзникам — если слой это разрешает: разведка у союзников общая). Перенос игрока на другой
  сервер, удаление и сброс — одна операция над его слоями, а не обход семи модулей.

### Форма

- **Сетка** — чанки 32×32 (как у земли), N каналов фиксированного типа (`u8`, `u16`, `u32`, `f32`) на тайл. Чанк
  заводится при первой записи: пустой слой ничего не весит, поэтому и разреженное (покрытие — десятки тысяч тайлов на
  карте в миллион) ложится в сетку. Земля — 4 канала `u8`, покрытие — 1 канал `u16`. Обзор — два слоя игрока: `sight` (виден сейчас; выводится
  из юнитов и зданий, не сохраняется) и `explored` (разведан; сохраняется): у каждого слоя одно правило сохранения.
- **Предметы** — записи с местом, разложенные по ячейкам: следы, месторождения. Запись — фиксированные поля, как у
  компонента; срок жизни — необязательное поле.

### Память игрока — одна для всех слоёв

Слой мира может быть **запоминаемым**: тогда у каждого игрока есть его версия — то, что он видел последним. Хранится
только расхождение с исходным (как у `landMemory` сейчас): тайлы и предметы, которые изменились с тех пор, как игрок их
видел. Одна система после обзора — `learn` — для всех запоминаемых слоёв сверяет изменённое в ячейках обзора игрока и
переносит увиденное в его версию. Память о земле, о покрытии, призраки месторождений — это одна и та же запоминаемость
трёх слоёв. Память о зданиях — то же для сущностей: снимок сущности, ушедшей из обзора.

Видит ли игрок тайл — слой обзора; что ему слать — его версия запоминаемых слоёв. Хосту не нужно знать, какие это
слои: он шлёт изменения версий игрока.

### Изменения и синхронизация — один формат

У каждого чанка — номер правки; слой знает изменённые чанки с прошлого раза. Изменение — `слой, игрок (или мир), чанк,
байты чанка` (предметы — записи ячейки). Этот формат — единственный:

- **Сохранение** — все чанки всех сохраняемых слоёв: раздел на слой мира, слои игрока — в записи игрока.
- **Зеркало TS ↔ Rust** (`boundary.md` (убран вместе с TS, в истории git)) — изменённые чанки после системы или тика. Позже TS читает чанки прямо из
  памяти wasm, без копии.
- **Сеть** — игроку: изменённые чанки его слоёв и его версий запоминаемых слоёв. При входе — все.
- **Мод** — тот же доступ: чанки слоя столбцами, запись — через буфер команд.

**[решено, 2026-10-16]** Союзники — флагом `allies` у слоя игрока: такой слой читают и союзники (обзор считается по
своим и союзным, как сейчас), а хранится он у каждого свой. Слоёв «команды» нет: союзы меняются на ходу, и общий слой
пришлось бы делить и сливать.

### Объявление

Слои мода `base` — данными (`packages/base/data/layers.json`), как таблицы юнитов; мод добавляет свои строкой. Пример
(в файле — полный список и пояснения `about`):

```json
{
  "land": { "scope": "world", "shape": "grid", "channels": ["u8", "u8", "u8", "u8"], "save": true, "remember": true },
  "paving": { "scope": "world", "shape": "grid", "channels": ["u16"], "save": true, "remember": true },
  "sight": { "scope": "player", "shape": "grid", "channels": ["u8"], "save": false, "allies": true },
  "explored": { "scope": "player", "shape": "grid", "channels": ["u8"], "save": true },
  "traces": { "scope": "world", "shape": "items", "cell": 16, "fields": { "kind": "u8", "tick": "u32" } },
  "radiation": { "scope": "world", "shape": "grid", "channels": ["f32"], "save": true }
}
```

Последняя строка — пример слоя мода: радиация после ядерного удара. Системы мода пишут в него столбцами, клиент
получает его тем же путём, что покрытие, и может рисовать.

Выводимые слои (занятость) не сохраняются и не шлются (`"save": false`, `"send": false`): их пересчитывает тот, кому
они нужны.

## 3. Открытые вопросы

- **Срок предметов** (следы истекают) — поле движка или дело системы.
- **Перенос игрока между серверами** — нужен ли (тогда запись игрока в сохранении — самодостаточный блок с его слоями).

## 4. Порядок

Старые слои в `sim-ts` не переписываются (она заморожена): единый механизм — в Rust, а TS-зеркала нынешних
интерфейсов (`Vision`, `Paving`, `Land`) читают его чанки.

- [x] С1. **Ядро слоёв** в `crates/engine` (`layers.rs`): объявление (`LayerSpec::parse_all`), сетка и предметы, слои
      мира и игрока (`add_player`, `forget_player`), изменённые блоки (`take_changes`), сохранение (`save`) и
      применение (`apply`) в одном двоичном формате (`encode`, `decode`). `packages/base/data/layers.json` — нынешние
      семь слоёв (обзор разделён на `sight` и `explored`); его читают крейт логики и `packages/tests/base.test.ts`.
- [ ] С2. **Зеркало слоёв** в `@kharos/sim-rust`: изменённые чанки в обе стороны, как журнал мира; `check` сверяет и
      слои.
      **[работа, 2026-10-16]** TS → Rust: слой в зеркале — объект `LayerMirror` (что изменилось с прошлого раза, все
      непустые блоки, байты блока в формате слоя); изменения идут одним буфером `encodeChanges` в `sim_layers`. `check`
      сверяет каждый слой зеркала с блоками Rust (`Layers::blocks`, `sim_layer`); пустой блок и отсутствующий — одно.
      Rust → TS — когда системы на Rust начнут писать в слои.
- [ ] С3. **Земля** — первый слой: системы на Rust читают местность.
      **[сделано, 2026-10-16]** Генератор на Rust (`crates/engine/src/terrain.rs`): перенос `terrain.ts` до байта —
      арифметика по правилам JS, синус, косинус и гипотенуза из `libm` (натив и wasm одинаковы). Сверка
      (`packages/tests/landRust.test.ts`): ноль расхождений на пяти настройках, а разово — на десяти картах 1024² (42 млн байт).
      В wasm карта 1024² собирается за 122 мс, у TS под JIT — 198 мс. Перед этим в TS исправлено: выводимое зависело от
      порядка сборки чанков (`docs/bugs.md`).
      **[сделано, 2026-10-16]** Земля в Rust-симуляции: `kharos_sim::Sim` — мир, земля и слои; земля строится из
      генератора с картой мира TS. Зеркало шлёт её изменениями слоя `land` в общем формате (`encodeChanges` в
      `@kharos/sim-rust` ↔ `layers::decode`): у загруженного мира — все чанки, дальше — чанки с правкой новее известной
      Rust (`land.revisions`) вместе с соседями, у которых пересчиталось выводимое. `check` сверяет каждый собранный в TS
      чанк с Rust — один раз и снова после правки; если Rust не принимает чанки, падают 13 тестов с правками карты и
      загрузкой. Осталось: системы на Rust, которые читают местность (движение, пути, стройка), — с переносом систем.
- [x] С4. **Покрытие** и **занятость**.
      **[сделано, 2026-10-16]** Покрытие — слой `paving` в зеркале: изменения ловятся на `lay`, `lift` и `clear`, блок —
      код тайла в `u16`. Если Rust не принимает слои, падают 9 тестов с покрытием.
      **[сделано, 2026-10-16]** Занятость Rust выводит сам (`crates/sim/src/occupancy.rs`) — наблюдателем мира
      (`World::observe`: события входа с данными на миг входа и выхода до снятия компонента, как `observe` в TS); `Sim::settle`
      разбирает их после чужого журнала и после каждой системы. Для этого журнал TS идёт в Rust с данными `add` и правками
      `set` по порядку. Зеркало занятость только сверяет; если Rust не освобождает тайлы снесённых, падают 46 тестов.
      Ячейки зданий для обзора (`inCell`) — с обзором, С5.
- [x] С5. **Обзор и разведанное** — слой игрока; система обзора на Rust.
      **[сделано, 2026-10-16]** Сначала в TS: обзор хоста пересчитывает только система `vision` (`strict`), а не первая
      спросившая система; новый игрок считается при первом вопросе. Копия клиента считает лениво, как раньше. Потом
      `crates/sim/src/vision.rs`: слои игрока `sight` и `explored`, дальность обзора из таблиц мода, союзники, вспышки
      радаров и ядерных взрывов; система `vision` на Rust. В `@kharos/sim-rust` `sim.vision` — обёртка над Rust: новый
      игрок заводится на мире этого мига (зеркало досылает его перед вопросом), а в режиме `check` обзор TS повторяет то же,
      и сверка сравнивает игроков и тайлы, когда сдвинулся счётчик `changed` у любой стороны. Сдвиг круга обзора на
      десятую тайла роняет 357 тестов. Ячейки зданий для обзора (`inCell`) — пока в TS: их читает память о зданиях (С6).
- [x] С6. **Память**: запоминаемость земли и покрытия, система `learn`; призраки месторождений; память о зданиях.
      **[решено, 2026-10-16]** Одно правило для запоминаемых слоёв: своё и союзное игрок узнаёт сразу, чужое — увидев,
      при сверке раз в 4 тика (обзор и так пересчитывается раз в 4 тика). Правка земли на виду доходит до 4 тиков
      позже, чем прежде. **[сделано, 2026-10-16]** В TS: `recall.ts` — память запоминаемого слоя (что знает игрок
      иначе, чем общее; несверенное по ячейкам; узнанное); земля и покрытие — его применения со своим общим (исходный
      тайл; «покрытия нет») и хозяином значения (у покрытия). Интерфейсы хоста и формат сохранения прежние.
      **[сделано, 2026-10-16]** На Rust: `crates/sim/src/recall.rs` — тот же механизм, слои `Kind::Land` и
      `Kind::Paving`; системы `updateLandMemory` и `updatePaveMemory` идут в Rust, если в Rust и обзор. Память в TS
      осталась зеркалом (её читают хост, редактор, сохранение): TS досылает изменённые тайлы, исходные тайлы земли и
      забытое редактором (`memory_input`), Rust отвечает узнанным (`memory_take`). В режиме check тень на `recall.ts`
      считает то же, и сверка сравнивает знание и узнанное за запуск. Память о зданиях — `build_memory.rs`: кто что
      запомнил и забыл, решает Rust (здания в обзоре — по ячейкам занятости, `in_cell`), а снимок здания снимает TS по
      событию — JSON тот же. Призраки месторождений — в С7, вместе с месторождениями.
- [x] С7. **Следы и месторождения** — предметы.
      **[сделано, 2026-10-16]** Следы на Rust (`crates/sim/src/traces.rs`): предметы слоя `traces`, система `traces`
      (колея по ходу наземных юнитов, срок, предел на тайл); следы боя TS кладёт сразу (`traces_add`), после системы
      забирает оставленные и убранные (`traces_take`) — по ним обёртка `Traces` держит список и ячейки для хоста.
      В режиме check прежние следы TS считают то же. Синус, косинус, арктангенс и гипотенуза в wasm — от хоста JS
      (импорт `math`, `crates/engine/src/math.rs`): `Math.hypot` в Bun на macOS — системный и округляет не так, как
      `libm` или V8, и бит-в-бит одинакового между движками нет.
      **[сделано, 2026-10-16]** Месторождения — слой `deposits` в зеркале: предмет — место, вид (номер в
      `DEPOSIT_TYPES`), запас. Изменения ловятся на взятии и сбросе клеток и по номеру правки слоя (тогда досылаются все
      клетки: их немного, правки редки); `check` сверяет блоки. Без досылки по правке падают 5 тестов, без взятия клеток —
      251. Генератор месторождений, смена выработанных (`renewDeposits`) и призраки ушедших переходят на Rust вместе с
      системой смены — когда её прочтёт что-то на Rust; до тех пор слой ведёт TS.
- [ ] С8. **Сохранение** слоёв по новому формату (слои игрока — в его записи) и **рассылка** из версий игрока — когда
      Rust станет по умолчанию (`docs/engine.md`, 9.7). Формат сохранения меняется — вайп, без переходов.
