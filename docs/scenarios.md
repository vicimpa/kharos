# Сценарии

Клиент умеет идти по сценарию на Luau без человека: проверять игру как игрок (тесты интерфейса и механик) и снимать
ролики со звуком. Код — `apps/client/src/scenario.rs`, `offline.rs` (звук), `record.rs` (видео).

## Запуск

```sh
cargo build --release -p kharos-client
target/release/kharos --scenario tests/scenarios/deploy.luau
```

| Флаг | Что делает |
|---|---|
| `--scenario файл.luau` | режим сценария |
| `--show` | окно видно (по умолчанию невидимо) |
| `--fps 60` | кадров в секунду времени игры |
| `--size 1280x800`, `--scale 1` | кадр в своём буфере: размер в логических пикселях и плотность; любой размер, хоть вертикальные `540x960 --scale 2` → 1080×1920 |
| `--no-ui` | мир без интерфейса; он всё равно считается, и щелчки по нему работают |
| `--record файл.mp4` | видео всего прогона (нужен `ffmpeg` в `PATH`) |
| `--sound` | со звуком: в записи — дорожкой |
| `--lang ru` | язык интерфейса |
| `--timeout 600` | предел, секунд игры: дольше — провал; со звуком — и длина счёта звука |

Код выхода — итог: 0 — сценарий дошёл до конца, 1 — упал (`s:check`, `s:fail`, ошибка Luau или игры) или не
уложился в `--timeout`.

Время игры — номер кадра ÷ fps, а не часы: прогон не зависит от скорости машины и повторяется байт в байт — и
картинка, и звук (зерно `math.random` клиентских скриптов постоянное; в игре — от часов). Работает быстрее реального
времени: развернуть MCV — 29 с игры за 4 с, с записью видео и звука — за 13. Настройки и сохранения — во временной
папке (`KHAROS_CONFIG`, если задано, — там).

## Файл сценария

```luau
return {
	-- Сам сценарий: сопрограмма в своей машине Luau, переживает смену партий.
	run = function(s)
		s:start("skirmish", { fog = false })
		s:wait(0.5)
		local mcv = s:client("mcv")
		s:click(mcv.x, mcv.y)
		s:check(s:ui_has("MCV"), "MCV не выбран")
		s:ui_click("Развернуть")
	end,

	-- Функции в машине клиента идущей партии: s:client("имя", аргументы) → client.имя(c, аргументы).
	client = {
		mcv = function(c)
			for _, e in c:each({ "Unit" }) do
				if c:mine(e) and c:proto(e).name == "mcv" then
					local at = c:get(e, "Position")
					local x, y = c:to_screen(at.x, at.y)
					return { x = x, y = y }
				end
			end
			return nil
		end,
	},

	-- Функции в машине хоста: s:host("имя", аргументы) → host.имя(ctx, аргументы); изменения применяются сразу.
	host = {
		credits = function(ctx, player)
			return require("@base/lib/wallet").credits(ctx, player)
		end,
	},
}
```

Файл выполняется в трёх машинах: в своей (`run`) и в машинах клиента и хоста каждой партии. Значения между ними
ходят как JSON: числа, строки, таблицы; `nil` — `nil`. Модули модов — `require("@base/lib/…")`.

## Что умеет `s`

| | |
|---|---|
| `s.frame`, `s.time`, `s.tick`, `s.fps` | кадр, секунды игры, тик хоста, частота кадров |
| `s:wait(секунды)`, `s:frames(n)` | ждать |
| `s:wait_for(проверка, секунды?, сообщение?)` | ждать, пока `проверка()` не вернёт правду; дольше — провал |
| `s:start(партия, настройки?)` | новая партия `games/партия` (настройки — как у `c.app:start`); ждёт её первого кадра |
| `s:client(имя, аргументы?)`, `s:host(имя, аргументы?)` | функции файла в машинах клиента и хоста |
| `s:click(x, y, кнопка?)` | щелчок в логических пикселях окна (`"left"`, `"right"`, `"middle"`): нажатие, отпускание и кадр на отклик интерфейса |
| `s:pointer(x, y)`, `s:pointer()` | указатель там или нигде (наведение, подсказки) |
| `s:key(имя)`, `s:hold(имя, зажата?)` | клавиша (`"escape"`, `"enter"`, `"a"`, `"1"`, `"shift"`); `hold` — зажать и отпустить |
| `s:type(текст)`, `s:wheel(строк)` | набор текста, колесо |
| `s:ui_rect(номер)` | место узла интерфейса по номеру (`id`) в прошлом кадре: `{ x, y, w, h }` или `nil` |
| `s:ui_texts()` | все надписи прошлого кадра: `{ text, id, x, y, w, h }` по порядку рисования |
| `s:ui_find(надпись)`, `s:ui_has(надпись)` | надпись целиком, а нет — где она встречается |
| `s:ui_click(номер или надпись, кнопка?)` | щелчок в середину узла или надписи |
| `s:ui(показывать)` | рисовать ли интерфейс с этого кадра |
| `s:shot(файл.png)` | снимок этого кадра, когда он нарисован |
| `s:record(файл.mp4)`, `s:stop()` | видео с этого кадра; запись сама кончается вместе со сценарием |
| `s:log(…)`, `s:check(условие, сообщение?)`, `s:fail(сообщение?)` | вывод и проверки |

Интерфейс сценарий видит по прошлому кадру, как и игрок: щелчок по кнопке, которая появится после выделения, — через
кадр после него (`s:click` сам ждёт отклика).

## Тесты

Сценарии `tests/scenarios/*.luau` проходит `cargo test` (`apps/client/tests/scenarios.rs`) — каждый в невидимом окне,
с пределом 300 с игры. Нужен GPU: окно невидимое, но настоящее. Режим без графики (только логика и интерфейс, для CI
без видеокарты) — позже.

## Звук и видео

Видео — кадры RGBA трубой в `ffmpeg` (H.264, `yuv420p`, crf 18), без кадров на диске. Звук (`--sound`) считается
офлайн: OfflineAudioContext крейта `web-audio-api` останавливается на каждом кадре и ждёт, пока главный поток
посчитает кадр игры, так что звук совпадает с картинкой до блока в 128 отсчётов (2,7 мс). Длина счёта задаётся
заранее — `--timeout`; к концу сценария остаток досчитывается без остановок, а дорожка (WAV) кладётся к видео (AAC).

Скрипты подачи, которым нужна случайность, берут её у `math.random` (его засевает приложение) или у `c.hash`, а не у
`os.time`: иначе прогон сценария не повторится.
